# QuantGuard Interview QA

## 为什么做这个项目？

为了把长期定投、短期交易、风控审核和模拟交易流程系统化，训练自己对金融业务建模、后端事务和自动化测试的理解。

## 个人负责什么？

负责后端架构、数据库设计、核心业务模块、异常处理、测试体系、GitHub Actions 和项目文档。

## 为什么选择当前技术栈？

Spring Boot 适合快速构建 REST API，MySQL 适合保存结构化交易数据，MyBatis-Plus 能减少基础 CRUD 代码并支持乐观锁，Testcontainers 能验证真实数据库行为。

## 架构如何划分？

采用标准分层：Controller 接收请求，Service 编排业务和事务，Mapper 访问数据库，DTO 隔离接口模型，Entity 对应数据库表。

## 最难的问题是什么？

最难的是订单、成交、资金流水和持仓更新的一致性，尤其是异常回滚和并发操作下不能出现重复成交或资金错乱。

## 如何测试？

使用单元测试验证业务规则，使用 MockMvc 验证接口错误响应，使用 Testcontainers MySQL 验证真实事务回滚和并发控制。

## 如何处理异常？

业务异常转换成明确的 HTTP 状态码，例如参数错误 400、资源不存在 404、资源冲突 409，未知异常返回 500 且不暴露堆栈。

## 如何保证数据一致性？

资金、订单、成交和流水写入放在事务内；并发更新检查受影响行数；需要并发控制的实体使用乐观锁版本字段。

## 当前不足？

没有真实行情、前端尚未完成、不接入券商、不做真实撮合和多用户权限。

## 下一步优化？

完善 V6 后续交易模块，之后实现前端、回测、策略展示和更完整的风险统计。
