# KMNZ Interview QA

## 为什么不用前端框架？

项目页面数量有限，内容以静态展示为主。原生技术减少部署和构建要求，也能直接练习 DOM、状态和响应式样式。

## 如何保持多页面一致性？

所有页面共享 `style.css`、主题模块和公共脚本。导航增强、主题按钮和部分内容由 JavaScript 统一注入，但 HTML 布局仍存在一定重复。

## 主题切换如何避免闪烁？

`theme.js` 在页面头部尽早加载，先读取 localStorage 或系统偏好，再设置根元素主题属性和浏览器主题色。

## 为什么同时支持 Firebase 和 localStorage？

Firebase 提供真实的云端认证入口，localStorage 让未配置外部服务时仍能演示完整页面流程。后者明确不是生产认证方案。

## 歌回封面如何导入？

用户输入媒体链接，脚本尝试调用接口或读取页面元数据。配置代理后可通过代理请求，否则可能受浏览器 CORS 限制。

## 如何验证？

本轮使用 Node 对所有 JavaScript 文件执行语法检查，并扫描所有 HTML 的本地链接，两项都通过；尚未建立 Playwright 等浏览器测试。

## 当前最大问题是什么？

演示认证会在 localStorage 保存用户数据，不适合真实账号；多页面共享结构难以统一维护；外部封面解析不够稳定。

## 下一步如何优化？

先增加浏览器测试和 CI，再抽取共享布局、明确认证模式，并部署到稳定的静态站点托管环境。
