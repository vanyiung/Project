# Content Guidelines

## 记录原则

- 只写有事实支撑的内容。
- 不确定内容使用 `待补充`、`待核验`、`规划中`、`未公开` 或 `CHANGE_ME`。
- 目标值不能写成已实现结果。
- 技术栈必须与实际项目一致。
- 不为了简历效果编造性能、用户、上线、准确率或奖项。

## 项目文档建议顺序

1. 项目背景和要解决的问题。
2. 当前状态和边界。
3. 技术栈和模块划分。
4. 个人负责内容。
5. 技术难点和解决方式。
6. 测试与验证记录。
7. 已知限制和下一步。

## 作品集表达

- 简历版保持简洁，突出技术职责和可验证成果。
- 面试版说明为什么这样设计、遇到什么问题、怎么验证。
- 答辩版突出项目背景、系统流程和个人贡献。

## 禁止内容

- 完整源码副本。
- 未脱敏截图。
- 真实 Secret。
- 真实个人身份信息。
- 未确认的成果。
- 大型构建产物或数据文件。
